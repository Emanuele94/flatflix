<objective>
Turn the runner into a real sandbox: one multi-stage Dockerfile builds the pinned Firecracker binary, a lean guest kernel and an ffprobe rootfs from scripts in the repo, and a hardened compose service runs it with only `/dev/kvm`, no capabilities, a read-only quarantine mount and no network egress. Then prove it end to end on the dev machine with real microVMs on generated fixtures, through the same judge the backend uses.

Purpose: QUAR-02 (fresh offline VM, read-only file, limits, timeout), QUAR-05 (pinned, built by repo scripts, no binaries committed, same build on WSL2 and Ubuntu), and QUAR-03's success criterion 3 on real files. Decisions D-68 (costly, settled), D-71 (amended 2026-10-23: no jailer), D-72, D-73, D-74 (built by `docker compose build`), D-75 (opt-in real suite).
Output: `sandbox/Dockerfile`, `sandbox/guest/{init,kernel.fragment}`, the sandbox service and network, infra invariants, the port/media doc rows, and the opt-in suite with its fixture generator.

Rules: English only. No binary is ever committed. Pinned versions live in Dockerfile ARGs with sha256 values from RESEARCH. The first `docker compose build sandbox` compiles a kernel (about 8 minutes on the dev laptop, longer on an N100); when a tool call has a shorter limit, run the build in the background and wait for it, then run the verify command.

D-73 is honoured as written: ffmpeg is pinned with `ARG FFMPEG_APK_VERSION=8.1.2-r0` and installed as `ffmpeg=${FFMPEG_APK_VERSION}` (apk verifies package signatures). RESEARCH Pitfall 11 / A3 suggested installing it unpinned because Alpine keeps only the current revision; with the pin, a new Alpine revision makes the build fail loudly and the admin bumps the ARG (plan 02.1-09 documents how).

The opt-in suite reaches the runner through `docker compose exec -T backend` (the backend is on the internal sandbox network). It does not publish port 8090: a port published on an `internal: true` network is not reachable, and adding a second, non-internal network would give the sandbox egress. RESEARCH Open Question 5 suggested an admin-override port; this plan chooses the exec route instead (flagged below).
