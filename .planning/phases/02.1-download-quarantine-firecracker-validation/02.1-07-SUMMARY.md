# Phase 02.1 Plan 07: Rejected Hand-off, Outcomes and Purge Summary

**A file that fails its sandbox check is probed once more, then held owner-only in `rejected/<id>/`, its torrent is deleted at once so a suspect file is never seeded, a six-key outcome sidecar keeps the household's row alive, the admin gets one audit line with the reason, and everything is purged after seven days; mixed packs deliver what passed, and a link that cannot be made never becomes a copy.**

## Performance

- **Duration:** 14 min
- **Completed:** 2026-10-23
- **Tasks:** 3 (1 tracer, 2 TDD)
- **Files:** 2 created, 6 modified; no package or lockfile change

## Accomplishments

- `OutcomeStore` (`outcomes.py`): `write` (validated 16-hex id, exactly id, name, type, kind, skipped, at, temp file `O_EXCL` mode 0600, fsync, `os.replace`), `get`, `load_all`, `remove`, `rejected_dir` and `purge`. Reads use `O_NOFOLLOW` and ignore directories, symlinks, extra or missing keys and interrupted temp files.
- `link_into_rejected` (`handoff.py`): folders 0700 (chmod after mkdir, umask-proof), the file hardlinked and set to 0600, same inode skipped, a stale file replaced; every error is a `HandoffError` carrying only an errno token.
- `link_into_media` takes the first free `<stem> (n)<ext>` for n = 2..99, reuses a target that is already the same inode, and raises `collision` only when all names are taken.
- Verifier: a probe whose status is not ok is repeated once (D-57); a refused path fails as `unprobeable` without a retry. Subtitles are checked only after a video passed. Outcomes `passed`, `partial` (ready sidecar, `skipped` = failing videos), `rejected` (no video passed or nothing to check, reason `no_video`), `held` (link failure) and the earlier `waiting` and `aborted`.
- The hand-off order is links, sidecar, audit lines, delete with files last, all under the torrent's lock with the 02.1-06 re-read, cancel and file-identity checks. A torrent with a stored outcome for the same completion is not probed again: its delete is retried.
- Each tick ends with `outcomes.purge` (a `quarantine.purged count=N` line only when N is above 0) and the seeding-end removal: a verified Film/SerieTV torrent in quarantine in `stoppedUP` or `pausedUP` gets a ready sidecar while it is inside the visible window, then `delete(deleteFiles=true)`, which removes only the quarantine link; the media hardlink keeps the film. qBittorrent's share-limit action stays "Stop" (`max_ratio_act` untouched).
- Lifespan: `app.state.outcomes = OutcomeStore(settings.rejected_root)` is created before the verifier and passed to it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] A stored outcome must not swallow a new download of the same film**
- **Found during:** Task 2
- **Issue:** the plan skips probing a torrent that already has a sidecar. A household member who fetches a rejected film again (same info-hash, same id) within seven days would have the new download deleted unchecked, and the ready row of an old film would too.
- **Fix:** the stored outcome is a pending delete only when `outcome.at >= completion_on` of the torrent in qBittorrent (a delete that failed earlier); a torrent that completed after the outcome was stored is checked like any other.
- **Files modified:** backend/app/quarantine/verifier.py
- **Commit:** `78166e5`

**2. [Rule 2 - Missing critical] An empty file list is not "nothing to check"**
- **Found during:** Task 2
- **Issue:** the plan rejects and deletes a torrent with no file to check. qBittorrent can answer `torrents/files` with an empty list before it has loaded a torrent, which would delete a household download because of a host fault (prohibition: never reject because of a host fault).
- **Fix:** no rows at all leaves the torrent Checking (`held`, nothing deleted); only a non-empty list with nothing checkable (samples, subtitles, excluded files) is rejected with `no_video`.
- **Files modified:** backend/app/quarantine/verifier.py
- **Commit:** `78166e5`

**3. [Rule 1 - Bug] A stale held file would make a returning torrent fail forever**
- **Found during:** Task 1
- **Issue:** a rejected film downloaded again within the retention finds its old held file at the same path; treating that as a collision would leave the torrent Checking with a link-failed line on every restart.
- **Fix:** `link_into_rejected` replaces a stale file (never a folder) in the backend-owned rejected folder; the same inode is left alone.
- **Files modified:** backend/app/quarantine/handoff.py
- **Commit:** `2f5a863`

**4. [Rule 3 - Blocking] The tdd-red-evidence record must live inside the project**
- **Found during:** Task 2 RED
- **Issue:** the classifier refuses a record path outside the project directory, so the scratchpad could not hold it.
- **Fix:** the record and junit report were written to a throwaway `.gsd-red-tmp/` folder inside the repo and removed before the commit; nothing was committed from it.
- **Files modified:** none committed
- **Commit:** none

**Total deviations:** 4 (2 missing-critical, 1 bug, 1 blocking tooling). **Impact:** none on the interface names and shapes consumed by plans 08 and 09. Deviation 1 and 2 make the plan's behaviour safer, not different for the cases it lists.
