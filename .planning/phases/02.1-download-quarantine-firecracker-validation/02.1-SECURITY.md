## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| admin env file -> backend settings | admin configuration decides where downloads land | save paths |
| qbittorrent / backend containers -> host DATA_ROOT | untrusted torrent payload on the host; backend has rw on the media tree | downloaded files |
| backend -> runner POST /probe | relative path derived from attacker-influenced torrent file names | path string |
| microVM serial console -> runner | output produced while parsing a hostile file | probe facts (untrusted) |
| runner -> backend facts | facts cross into the deciding component | ProbeFacts JSON |
| downloaded subtitle bytes -> check_subtitle | the only host-side read of downloaded content | subtitle text (capped) |
| API JSON -> DOM | torrent names are attacker-controlled text | names, counts |
| Internet build inputs -> sandbox image | Firecracker tarball, kernel source, Alpine packages | build artifacts |
| VM -> Firecracker -> sandbox container -> host | escape path | none intended |
| verifier -> media / rejected folders | step that makes a file visible to Jellyfin, or holds a suspect file | hardlinks |
| verifier / backend -> qBittorrent torrents/delete | destructive call with deleteFiles decided server-side | torrent ids |
| torrent names -> audit log | attacker-controlled text reaches the admin's log | escaped names |
| browser -> DELETE /api/downloads/{id} | opaque untrusted id | HMAC id |
| doctor output, smoke.py, docs -> admin / public repo | diagnostics and public guide | names, counts, placeholders |

## Accepted Risks Log

| Risk ID | Threat Ref | Rationale | Accepted By | Date |
|---------|------------|-----------|-------------|------|
| AR-01 | T-02.1-02 | The backend runs as PUID:PGID with rw on DATA_ROOT because `link()` needs the owner's uid under `fs.protected_hardlinks`. The browser sends no path, the API has no file-writing route (`DownloadRequest` is `extra="forbid"`), and the container has no other privilege (`infra::test_backend_runs_as_the_media_owner`). | project owner (plan-time disposition) | 2026-10-25 |
| AR-02 | T-02.1-25 | The per-file `chmod 0600` on held files was removed by CR-01 (f4b87db): a hardlink shares its inode with the quarantine name, so the chmod locked the sandbox uid out and stalled the queue. Held files keep qBittorrent's mode and may keep exec bits. The remaining control is the 0700 `rejected/` folders, which keep other host users out, and nothing ever executes or opens these files. Optional hardening later: clear only exec bits (`mode & ~0o111`). | project owner (UAT security gate) | 2026-10-25 |

*Accepted risks do not resurface in future audit runs.*

Informational (not threats, unfixed review items): IN-01 `handoff.py` `os.makedirs` creates the rejected root with the umask default if `init-host-dirs.sh` was never run (per-torrent subfolders stay 0700). IN-04 the runner HTTP server has no socket timeout.
