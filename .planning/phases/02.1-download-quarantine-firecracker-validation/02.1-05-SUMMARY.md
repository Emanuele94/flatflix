# Phase 02.1 Plan 05: Sandbox Image and Real-VM Proof Summary

**One `docker compose build sandbox` builds checksummed Firecracker 1.17.0, a lean Linux 6.18.58 guest kernel and an Alpine 3.24.3 ffprobe rootfs into a hardened, cap-less, internal-network service; real microVMs on generated fixtures reach the decided verdicts through the backend's judge.**

## Accomplishments

- Tracer: build, start, `POST /selftest` through the backend container answers `ok` from a real microVM; `/health` reports `kvm: true`, firecracker 1.17.0, kernel 6.18.58, alpine 3.24.3, ffmpeg 8.1.2-r0. From the sandbox container, `http://1.1.1.1` gives "Network is unreachable" (internal network works).
- The sandbox service runs as 10002:10002 with the KVM group, only `/dev/kvm`, read-only root, `cap_drop: [ALL]`, `no-new-privileges`, Docker's default seccomp, `pids_limit 64`, `mem_limit 768m`, tmpfs work dirs, no `env_file`, no published port, and only `quarantine` mounted read-only (T-02.1-17, T-02.1-18, T-02.1-19).
- Infra suite: `check_sandbox` reports every weakening; 19 mutated variants each fail the matching check; network `sandbox` is `internal` and shared by backend and sandbox only; the backend has no `depends_on` for it; no kernel, rootfs, `.img`, `.tgz` or `firecracker` file is tracked, no NUL bytes under `sandbox/`, the Dockerfile pins and checks both downloads (T-02.1-16, T-02.1-20).

- No package or lockfile change: `git diff --exit-code -- backend/uv.lock frontend/package-lock.json` is clean (T-02.1-SC).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] fx-versions took the ffmpeg description instead of the version**
- **Found during:** Task 1 (first real run of `/health`)
- **Issue:** `apk info -v ffmpeg` prints the package description, so `ffmpeg=` held "ffmpeg: Complete and free Internet live audio..."
- **Fix:** read the `V:` line of the `P:ffmpeg` record from `/rootfs/lib/apk/db/installed` (now `8.1.2-r0`).
- **Files modified:** sandbox/Dockerfile
- **Commit:** `932a085`

**2. [Rule 2 - Missing critical] sandbox/.dockerignore**
- **Found during:** Task 1
- **Issue:** the plan did not mention a build-context filter; `sandbox/tests` and `__pycache__` would be sent to the build and could end up in `runner/`.
- **Fix:** added `sandbox/.dockerignore` (tests, caches).
- **Commit:** `932a085`

**3. [Rule 2 - Design] Versions declared once**
- **Issue:** the plan repeats the Firecracker and kernel version in several stages; fx-versions could drift from what was downloaded.
- **Fix:** global ARGs before the first FROM, re-declared in each stage.
- **Commit:** `932a085`

**4. [Plan sequencing] Task 1 commit holds only the networks edit of the compose test**
- The full invariant tests of Task 2 were temporarily set aside so each commit stays atomic.

**Total deviations:** 4 (1 bug, 2 missing-critical/design, 1 sequencing note). **Impact:** none on the plan's interfaces.
