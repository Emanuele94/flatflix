## Fixed Issues

### CR-01: chmod 0600 on a hardlinked rejected file locks the sandbox out of the quarantine file

**Files modified:** `backend/app/quarantine/handoff.py`, `backend/tests/test_quarantine_verifier.py`, `docs/setup.md`
**Commit:** f4b87db
**Applied fix:** Dropped the `os.chmod(dst, 0o600)` in `link_into_rejected`. The 0700 rejected folders are the barrier. Two tests that asserted a 0600 held file now assert the folder mode; a new regression test checks that the shared inode keeps its mode. The setup guide no longer claims held files are 0600.
**Not done:** the second suggestion ("treat a runner `permission` answer as a per-file problem after N tries") was left out; with the chmod gone the trigger is gone, and a `permission` answer is still a host fault by design (D-58).

### CR-02: Any 400/404/409 from SANDBOX_URL becomes a verdict that deletes the torrent

**Files modified:** `backend/app/quarantine/verifier.py`, `backend/app/quarantine/runner_client.py`, `backend/app/tools/doctor.py`, `sandbox/runner/server.py`, `backend/tests/fakerunner.py`, `backend/tests/test_quarantine_verifier.py`, `backend/tests/test_runner_client.py`, `backend/tests/test_doctor_sandbox.py`, `sandbox/tests/test_runner_api.py`, `docs/setup.md`
**Commit:** 1099284
**Status:** fixed: requires human verification (logic change)
**Applied fix:**
- Verifier: only `not_regular_file` stays a per-file `unprobeable`. `not_found`, `invalid_path` and `invalid_json` now record runner outage `path_mismatch` and stop the tick with "waiting"; nothing is linked, rejected or deleted.
- Client: a 400/404/409 counts as a refusal only when the body carries one of the runner's own error codes. A bare status, an HTML body or another service's JSON becomes `RunnerUnavailable("unexpected_status")`.
- Runner: an unknown route answers 404 `{"error":"unknown_route"}`, distinct from file-not-found.
- Doctor: new `canary_check` writes a small 0644 file into quarantine, asks the runner to probe it and prints `sandbox sees the quarantine folder`, or a FAIL line with a token if the runner refuses it. It runs only when the runner health and selftest lines pass. FakeRunner gained `answer_unscripted`.
- Tests: new verifier test for 400/404 (waits, one audit line, nothing deleted, recovers once fixed); client tests for the contract-body rule; doctor canary tests; runner API test for `unknown_route`.
- Note for the stack: the sandbox image must be rebuilt for the `unknown_route` answer. Even without the rebuild, an old runner's 404 `not_found` now makes the verifier wait.
