## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> DELETE /api/downloads/{id} | opaque id, untrusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-29 | Tampering / information loss | deleteFiles decision | high | mitigate | `delete_files_for` keys on the save path read inside the request: true only under quarantine (where the media hardlink keeps verified films), Phase 2 rule for legacy rows; parametrized table and surviving-link test |
| T-02.1-30 | Tampering | cancel racing the verifier | medium | mitigate | `request_cancel` before the job cancel, delete inside the same per-torrent lock the verifier hands off under; test with a paused probe |
| T-02.1-31 | Tampering (IDOR) | DELETE on outcome rows | medium | mitigate | Outcome ids are the same HMAC ids; only kind ready can be removed (sidecar only); check_failed answers 404; ids validated by the existing 16-hex path pattern |
| T-02.1-32 | Information Disclosure | list items | medium | mitigate | Eight fixed keys, no path, hash, category name or reason; no-leak canary flow with quarantine rows and outcomes; smoke leak markers for /quarantine, /rejected, /data/ |
| T-02.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package added; `git diff --exit-code -- backend/pyproject.toml backend/uv.lock` stays clean |
