## Accomplishments

- Tracer: a finished torrent saved under quarantine reads `checking` (action cancel, no ETA) until it carries `fx-ok-<t>`, then `ready` with action remove. Every list item now carries `skipped`, so all rows have exactly eight keys.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A raised cancel flag outlived its cancel**
- **Found during:** Task 3 (design of the guard wiring)
- **Issue:** `HandoffGuard` only drops a flag when the verifier's next tick sees the torrent gone. A torrent added again under the same info-hash within that window (the existing "download again at once" flow), or a Cancel whose delete failed with nothing left to retry it, would keep the flag and the verifier would skip that torrent's check for good, leaving it Checking until Problem.
- **Fix:** new `HandoffGuard.clear_cancel(hash)` (drops the flag only, never the lock, because a waiter may hold it). `cancel` calls it after a successful delete, and on a failed delete when no job sweep will retry. Tests: `test_a_torrent_added_again_after_a_cancel_is_checked`, `test_a_failed_delete_lowers_the_flag_so_the_torrent_can_still_be_checked`. The race test therefore asserts the flag and the held lock at delete time (recorded by a spy on the fake delete) instead of the flag afterwards.
- **Files modified:** backend/app/quarantine/guard.py, backend/app/download/pipeline.py, backend/tests/test_download_cancel.py
- **Commit:** c3c4d11

**2. [Rule 3 - Blocking] Test rig rebuilt the pipeline without the guard and the outcome store**
- **Found during:** Task 3
- **Issue:** `Rig.use_sleep` in `test_download_pipeline.py` constructs its own `DownloadPipeline`; without `guard=` and `outcomes=` the rebuilt pipeline would not share the app's guard and could not remove outcome rows.
- **Fix:** it passes `state.guard` and `state.outcomes`. Tests that swap `app.state.outcomes` for a temporary folder use an `install_store` helper that rebuilds the pipeline with the same store.
- **Files modified:** backend/tests/test_download_pipeline.py, backend/tests/test_download_cancel.py
- **Commit:** c3c4d11

### Plan-shape notes (not defects)

- A new test file, `backend/tests/test_smoke_contract.py`, holds the smoke tests (the plan allowed importing `scripts/smoke.py` by path; it listed no file for them). `check_item(item)` was extracted from `check_downloads_list` as the plan suggested.
- `CancelOutcome.action` is now `row_action(row)` instead of "cancel if files were deleted else remove". For a quarantine torrent the audit action therefore follows the button (a verified film's Remove logs `remove` although `deleteFiles=true`), and for a torrent that vanished mid-cancel it reports the action of the first read.
- The ordering stamp of a verified ready row is its fx-ok time (it also drives the window), so ready rows sort newest-verified first.
