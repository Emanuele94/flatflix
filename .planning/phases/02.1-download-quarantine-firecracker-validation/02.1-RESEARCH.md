## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Host layout and hand-off
- **D-44:** One **`DATA_ROOT`** parent replaces the separate `MEDIA_ROOT` / `INCOMPLETE_DIR` roots: `DATA_ROOT/{media/Film, media/SerieTV, quarantine/Film, quarantine/SerieTV, rejected, incomplete}`. qBittorrent and the backend mount `DATA_ROOT` as **one** bind mount, so hardlinks work. Jellyfin (Phase 4) will mount only `media` read-only. `docs/ports-and-media.md`, `scripts/init-host-dirs.sh`, `.env.example`, compose and the infra tests are updated to match. — **Reversibility:** costly — changes the documented media contract, compose mounts, env names and infra invariant tests; the existing host folders must be moved by the admin.
- **D-45:** qBittorrent category save paths point at `quarantine/<Category>` (not media). Admin-added Film/SerieTV torrents go through the **same pipeline** (D-34 spirit); nothing bypasses the check.
- **D-46:** Passing files are **hardlinked** into `media/<Category>`, keeping the torrent's relative folder structure minus rejected files and dotfiles (`.<hash>.parts`). The torrent keeps seeding from quarantine under D-21. Phase 4 renaming will apply to the link. — **Reversibility:** costly — Phase 4 builds its rename on top of the link-based hand-off.
- **D-47:** When seeding ends (D-21 share limit reached) or the user taps "Remove from list" (D-33), the torrent is removed with **`deleteFiles=true`**. That deletes only the quarantine link; the media hardlink keeps the film, so D-33's "the film is never deleted from the phone" still holds. **D-33 is amended:** deleteFiles=false becomes true, because the files now live on through the media link.
- **D-48:** If the hardlink fails (e.g. EXDEV: `DATA_ROOT` spans two filesystems), **never fall back to copy**. Log the error, keep the row in Checking, and have the doctor check at startup that quarantine and media share one filesystem.
- **D-49:** Files already in the media folders from Phases 1–2 are **left as they are**. `docs/setup.md` notes that only post-2.1 downloads are verified. No migration code.

#### Pipeline trigger and states
- **D-50:** A **backend background poller** (~10 s, inside the FastAPI lifespan like the bootstrap task) finds completed Film/SerieTV torrents not yet verified. It works with no phone open and re-scans after a restart. No qBittorrent "run on completion" hook.
- **D-51:** Verification starts when the **whole torrent** completes (one trigger per torrent, not per file).
- **D-52:** **One probe at a time** (serial queue). A 10-episode pack means ~10 VM boots in sequence.
- **D-53:** New plain state **"Checking…"** (QUAR-04's "verifying") between Downloading and Ready. "Ready" only after the hand-off. **Cancel is allowed during Checking** (one confirm, as D-32) and deletes the quarantine files.
- **D-54:** Verification state must **survive a backend restart**, derived from disk and/or qBittorrent (e.g. a qBittorrent tag or a marker in `rejected/`), not only the in-memory job registry. A restart mid-check re-runs the check.

#### Rejected files
- **D-55:** A failing file is **moved to `rejected/`** (outside Jellyfin's reach, owner-only, never executable) and **auto-purged after 7 days** (env-configurable, same default as D-28).
- **D-56:** The user sees a plain message on the row: **"This file didn't pass the safety check. Try another result."** (new `messages.js` entry). The row stays **24 h** like other failures (D-29) and has **no actions**.
- **D-57:** A **probe crash or timeout** gets **one retry in a fresh VM**. If the retry also fails, the file is rejected (QUAR-02).
- **D-58:** If the **runner itself is unavailable** (no `/dev/kvm`, sandbox service down), files **stay in quarantine** and the row stays in Checking. The admin log and the doctor flag it, and the check retries when the runner is back. **Never fail open, never reject because of a host fault.**
- **D-59:** **No admin override** in 2.1. Releasing a false rejection is a documented manual host step (move the file from `rejected/` into `media/<Category>`).
- **D-60:** The admin learns about rejections from a **`quarantine.rejected` audit line** (torrent name, file, reason, short probe summary) in the existing stdout trail (D-40/D-41). The doctor also reports the count of held files. No reason files on disk.

#### Multi-file torrents
- **D-61:** In a **mixed pack** (e.g. 9 of 10 episodes pass), the passing files are linked into media and the failing ones moved to `rejected/`. The row shows **Ready with a note** ("1 file didn't pass the safety check"). Then the torrent is **removed at once with deleteFiles=true**: a torrent that contained a suspect file is never seeded.
- **D-62:** **Subtitles** (`.srt .ass .ssa .sub .idx`) are not probed in the VM. Text subtitles get a size cap plus a valid-text check (no binary); `.sub/.idx` get a size cap only. They move only if **at least one video from the same torrent passed**.
- **D-63:** Films: **every passing video except samples** moves (same "sample" naming rule as the D-43 main-video choice), so extras can reach Jellyfin.

#### Validation rules (QUAR-03)
- **D-64:** **Duration minimum:** film main video ≥ **40 min**, each series video ≥ **10 min**. Env-configurable, no upper bound. In a film torrent the minimum applies to the **main video only**; extras must still be real videos and pass the bitrate band.
- **D-65:** **Size plausibility = bitrate band:** size / duration between ~**100 kbps** and ~**100 Mbps** (env-configurable).
- **D-66:** **Container ↔ extension, strict family map:** `.mkv` → matroska (the matroska/webm demuxer), `.mp4`/`.m4v` → mov/mp4 family, `.avi` → avi. A mismatch is rejected.
- **D-67:** **Codec:** any real video codec ffprobe recognizes. Attached-picture / cover-art streams (`disposition.attached_pic`) do not count as video. This is a safety check, not a TV-compatibility check.

#### Runner (sandbox) architecture (QUAR-02, QUAR-05)
- **D-68:** The runner is a **separate compose service** (e.g. `sandbox`) with `devices: /dev/kvm`, **not privileged**, on its own internal network with **no egress**. **Research must prove `/dev/kvm` works in a container under Docker Desktop (WSL2 dev)** as well as on native Docker Engine (Ubuntu Server). If Docker Desktop cannot pass it through, document a fallback rather than redesign. — **Reversibility:** costly — compose topology, networks and infra invariant tests depend on it.
- **D-69:** **Interface:** a small HTTP API, e.g. `POST /probe {relative path}` → JSON facts. The backend sends only paths relative to the quarantine root; the runner resolves them under that root only and refuses traversal. This is the "one stable interface" of QUAR-05. — **Reversibility:** costly — the contract is what makes the sandbox swappable; changing it touches both sides and tests.
- **D-70:** **The runner returns facts, the backend judges.** The runner returns parsed ffprobe facts (format name, streams with codec type/name/disposition, duration, size, exit/timeout status). The backend applies D-64..D-67, so thresholds are unit-testable without KVM and survive a sandbox swap.
- **D-71:** **Firecracker jailer** per VM (chroot, seccomp, cgroups, unprivileged uid) inside a hardened container: cap_drop ALL plus only what the jailer needs, read-only container rootfs, quarantine mounted **read-only**. In the VM: **no network device**, the file attached **read-only**, fresh VM per file, destroyed after.
- **D-72:** VM limits default to **1 vCPU, 256 MB, 60 s** wall-clock (covers boot + probe + shutdown). Env-configurable.
- **D-73:** **Guest image:** pinned Alpine release + pinned `ffmpeg` apk (checksummed), built into a small ext4 rootfs with a tiny init that runs ffprobe, writes JSON to the console/a vsock or output device, and powers off. The guest kernel is built from a pinned source/config by a script. **Pinned Firecracker release**, downloaded checksum-verified.
- **D-74:** The kernel, rootfs and Firecracker binaries are **built into the sandbox image** by a multi-stage Dockerfile, so `docker compose build` does it all, the same on WSL2 and Ubuntu. No binaries are committed (QUAR-05).

#### Testing
- **D-75:** The default test suites use a **fake runner** (no KVM). An **opt-in real-sandbox suite** (marker like the existing `-m integration` guard) runs real microVMs against generated fixtures: a real short video, a renamed executable, a truncated file, a text file, a container/extension mismatch.
- **D-76:** `scripts/smoke.py` is extended so the Blender download goes **Downloading → Checking → Ready** and the file appears under `media/<Category>`. The rejection path is covered by the D-75 fixtures, not by a live torrent.

## Summary

The sandbox works. On this dev machine (WSL2 + Docker Desktop 29.7.2, Intel i7-1165G7) a Firecracker v1.17.0 microVM booted inside an unprivileged container (`--user 10001 --cap-drop ALL --read-only --network none --security-opt no-new-privileges`) with only `--device /dev/kvm` and `--group-add 993` added, probed five fixture files with ffprobe from Alpine 3.24.3 (ffmpeg 8.1.2) and powered itself off. With a lean guest kernel one probe takes about 0.5 s of VM time (1.45 s total including `docker run` overhead). D-68's "prove /dev/kvm in a container under Docker Desktop" is therefore settled with no fallback needed.

Four things the CONTEXT decisions did not anticipate, each reproduced here: (1) **D-71's jailer cannot run in a normally hardened container**: under Docker's default seccomp profile `pivot_root` fails with EPERM even with `CAP_SYS_ADMIN`; it only worked with `seccomp=unconfined` plus SYS_ADMIN, MKNOD, CHOWN, SETUID, SETGID, SYS_CHROOT, DAC_OVERRIDE, FOWNER, and it cannot hardlink a file out of a read-only mount (EXDEV), so the multi-GB film would have to be copied into the jail. Recommendation: drop the jailer, keep Firecracker's built-in seccomp, and let the hardened container be the jail (needs user confirmation, see A1). (2) **Attaching the file as a bare virtio disk breaks MP4**: the block device is cut to whole 512-byte sectors and ffmpeg's `file` protocol reports `st_size` 0 for a block device, so an MP4 with a trailing `moov` atom failed with "moov atom not found" and AVI lost its duration; the fix (a second 512-byte tail drive plus `concat:`/`subfile` in ffprobe) is verified. (3) **The backend must run as `PUID:PGID`**: with `fs.protected_hardlinks=1`, uid 10001 (the current backend user) and root-without-caps both get EPERM on `link()` for files owned by qBittorrent; uid 1000 works; two bind mounts give EXDEV. (4) **A full Firecracker guest config is too slow to build** (did not finish in 22 minutes on 8 threads, compiling `drivers/media`); a 38-line fragment on `tinyconfig` built a 13.6 MB `vmlinux` in 7m50s and boots the probe.

**Primary recommendation:** Build a stdlib-only runner service (`sandbox/`) that runs `firecracker --no-api --config-file` directly (no jailer) in a hardened, cap-less, read-only, `internal`-network container, attaches the quarantined file read-only plus a 512-byte tail drive, frames ffprobe output with a per-VM nonce on the serial console, and returns facts over `POST /probe`; implement the judge, verifier, hardlink hand-off and outcome store in `backend/app/quarantine/`, and run the backend as `PUID:PGID` on one `DATA_ROOT` bind mount.

## Architecture Patterns

### System Architecture Diagram

```
 phone ──HTTP──> web(Caddy :80) ──/api/*──> backend (FastAPI, user PUID:PGID)
                                              │  lifespan tasks: bootstrap, verifier loop (10 s)
                                              │
        ┌─────────────────────────────────────┤ every 10 s
        │ 1. torrents_info()  ────────────────┼──> qBittorrent (net: qbit)  saves into  DATA_ROOT/quarantine/<Cat>
        │    candidates = category Film/SerieTV, finished, save_path under quarantine, no fx-ok tag
        │ 2. torrents_files(hash) → videos (allowlist, prio>0, on disk) + subtitles
        │ 3. for each video, serially:
        │      POST /probe {"path": "Film/<rel>"}  ──(net: sandbox, internal, no egress)──┐
        │                                                                                  ▼
        │                                         sandbox runner (container, no caps, ro rootfs, quarantine mounted ro)
        │                                           validate path under quarantine root; stat; tail file (≤511 B, tmpfs)
        │                                           write vm.json; run `firecracker --no-api --config-file` (timeout 60 s)
        │                                              └─ microVM: 1 vCPU, 256 MiB, no NIC
        │                                                  vda = rootfs.ext4 (ro)  vdb = the file (ro)  vdc = tail (ro)
        │                                                  init: ffprobe → serial console, nonce-framed → reboot -f
        │                                           parse console → JSON facts  ◄───────────┘
        │ 4. judge(facts)  (pure, backend)  → pass / fail(reason)
        │      runner 503 (host fault)  → leave in Checking, retry next tick (D-58)
        │      timeout/crash            → one retry in a fresh VM (D-57), then fail
        │ 5. hand-off (ordered, idempotent, no copy):
        │      all pass : os.link → media/<Cat>/<rel>; tag fx-ok-<epoch>; torrent keeps seeding
        │      mixed    : link passes → media; link fails → rejected/<id>/; outcome sidecar; delete torrent deleteFiles=true
        │      all fail : link fails → rejected/<id>/; outcome sidecar; delete torrent deleteFiles=true
        │ 6. purge: rejected/<id>/ and sidecars older than retention; stopped+verified torrents → delete deleteFiles=true
        └─────────────────────────────────────
 GET /api/downloads → build_items(rows, outcomes, jobs) → states preparing/downloading/stalled/checking/ready/check_failed/problem/...
```

### Pattern 1: Run Firecracker directly in the hardened container (VERIFIED)
**What:** `firecracker --no-api --config-file /run/fx/vm-<id>.json`, one process per probe, killed by the runner after the wall-clock limit. Firecracker keeps its own seccomp filter (default on; `--no-seccomp` is flagged "Not recommended" in `--help`).
**When to use:** always for this phase (see A1).
**Example (the command that ran on this machine):**
```bash
docker run --rm --device /dev/kvm --user 10001:10001 --group-add 993 \
  --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp \
  --network none -v "$PWD/run:/work:ro" -v "$DATA:/data:ro" alpine:3.24.3 \
  /work/probe.sh /data/quarantine/Film/good.mkv
```
```json
{
  "boot-source": {"kernel_image_path": "/work/vmlinux-lean",
                  "boot_args": "console=ttyS0 reboot=k panic=1 pci=off loglevel=3 8250.nr_uarts=1 root=/dev/vda ro init=/init fxnonce=<hex> fxsize=<bytes>"},
  "drives": [
    {"drive_id": "rootfs", "path_on_host": "/work/rootfs.ext4", "is_root_device": true,  "is_read_only": true},
    {"drive_id": "probe",  "path_on_host": "<quarantined file>",   "is_root_device": false, "is_read_only": true},
    {"drive_id": "tail",   "path_on_host": "/tmp/tail.bin",        "is_root_device": false, "is_read_only": true}
  ],
  "machine-config": {"vcpu_count": 1, "mem_size_mib": 256, "smt": false}
}
```
There is no `network-interfaces` key: the guest has no NIC. Build this JSON with `json.dumps`, never string formatting (the path comes from a filesystem). `reboot=k` plus `reboot -f` in the guest makes Firecracker exit 0 ("Firecracker exiting successfully. exit_code=0").

### Pattern 2: Exact-bytes attach (VERIFIED; fixes a real false-reject)
**What:** A virtio disk holds whole 512-byte sectors, so Firecracker cuts the file ("Disk size 1659307 is not a multiple of sector size 512; the remainder will not be visible to the guest"). The runner writes the last `size % 512` bytes into a 512-byte zero-padded tmpfs file and attaches it as a third drive. In the guest, ffprobe reads both pieces through ffmpeg's own protocols, each wrapped in `subfile` to give it an exact size (a block device reports `st_size` 0 to ffmpeg's `file` protocol):
```sh
# guest /init (fxsize comes from the kernel command line)
TAIL=$((SIZE % 512)); FLOOR=$((SIZE - TAIL))
if [ "$TAIL" -eq 0 ]; then SRC="subfile,,start,0,end,${SIZE},,:/dev/vdb"
else SRC="concat:subfile,,start,0,end,${FLOOR},,:/dev/vdb|subfile,,start,0,end,${TAIL},,:/dev/vdc"; fi
timeout -s KILL 40 ffprobe -v error -hide_banner -protocol_whitelist file,concat,subfile \
  -format_whitelist matroska,webm,mov,mp4,avi -of json \
  -show_entries 'format=format_name,duration,nb_streams:stream=index,codec_type,codec_name,duration,width,height:stream_disposition=attached_pic' \
  "$SRC" >/tmp/out.json 2>/tmp/err.txt
```
Results of the three variants on the same `good.mp4` (moov atom last, 1,669,418 bytes, 298 bytes past a sector boundary): bare `/dev/vdb` -> "moov atom not found"; `concat` with unsized `file` parts -> "moov atom not found"; `concat` of `subfile` pieces -> `format_name mov,mp4,m4a,3gp,3g2,mj2`, duration 60.023152. `good.avi` lost its duration with the unsized variant and has it with `subfile`. Because `subfile` makes the demuxer's size exact, adding `size` to `-show_entries` gives a cross-check against the host `stat` size.

### Pattern 3: Nonce-framed console output (VERIFIED)
**What:** The runner generates `secrets.token_hex(8)` per VM and passes it as `fxnonce=` on the kernel command line. The guest prints `FXP:<nonce>:BEGIN`, `...:EXIT:<rc>`, `...:JSON`, the JSON, `...:ERR`, at most 1 KiB of stderr passed through `sed "s/[^ -~]/?/g"`, and `...:END`. The host parses only lines carrying the nonce, strips `\r`, and caps the bytes it reads from Firecracker's stdout (for example 256 KiB). Reasons: stdout and stderr of ffprobe interleave on the serial console (seen in the first run), ffmpeg colours errors with ANSI escapes unless `AV_LOG_FORCE_NOCOLOR=1`, and the console also carries kernel messages.

### Pattern 4: Host fault vs file fault (rule for D-57 vs D-58)
- No `FXP:<nonce>:BEGIN` seen (kernel never reached init, `/dev/kvm` EACCES, Firecracker failed to start, artifact missing) -> **runner fault**: answer HTTP 503 `runner_unavailable`; backend leaves the row in Checking.
- `BEGIN` seen, then wall-clock timeout, or `EXIT` is 137/143/139 or any non-zero, or the JSON is missing/invalid -> **file fault**: return `status: "timeout"` or `"probe_failed"`; backend retries once in a fresh VM (D-57), then rejects.
- `EXIT:0` with parseable JSON -> `status: "ok"`.

### Pattern 5: Hand-off ordering that survives a crash (D-46, D-54, D-61)
Every step is idempotent and the torrent is touched last, so a restart at any point just re-runs the check:
1. `os.link(src, dst)` each passing file into `media/<Cat>/<relative path>` (create parents with `os.makedirs(..., exist_ok=True)`); if `dst` exists and has the same `st_ino`, skip; a different inode is a name collision (see Open Questions).
2. Link each failing video into `rejected/<id>/<relative path>` (hardlink, not rename: renaming a file out of a live torrent would leave a `missingFiles` torrent after a crash). `<id>` is `download_id(secret, hash)`, so no info-hash touches disk.
3. Write the outcome sidecar atomically (`tmp` + `os.replace`) before the torrent disappears.
4. Pass-only torrent: add tag `fx-ok-<epoch>` (the `<epoch>` gives D-28's "7 days from Ready" without extra storage). Mixed or failed torrent: `delete(hash, delete_files=True)`.
Before step 1, compare `(st_ino, st_size, st_mtime_ns)` with the values taken before the probe and re-probe on any change (TOCTOU between probe and link). Take a per-torrent `asyncio.Lock` shared with the cancel path and check a "cancel requested" flag immediately before step 1, so a Cancel tapped during a probe cannot put a film into media.

### Anti-Patterns to Avoid
- **Passing the file as a bare `/dev/vdb` to ffprobe:** false rejects for MP4/AVI (Pattern 2).
- **Hardlink via two bind mounts or as a non-owner uid:** EXDEV / EPERM (Pitfalls 6, 7). Never fall back to copy (D-48).
- **Enumerating files with `os.walk` on the quarantine folder:** picks up `.<hash>.parts` and priority-0 leftovers. Use `torrents/files` (priority > 0, progress 1, exists on disk).
- **Trusting the filename or extension anywhere past the allowlist:** the extension only selects which container family to expect (D-66).
- **Deleting the torrent before the links and the outcome sidecar exist:** the household would see the row vanish.
- **Using `max_ratio_act` RemoveWithContent as the D-47 mechanism:** it is a global setting and would delete a still-unchecked torrent's quarantine files if the ratio is reached while the check is queued. Keep action 0 (Stop; `bootstrap.py` sets `"max_ratio_act": 0`) and let the backend purge stopped + `fx-ok-` torrents with `deleteFiles=true`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Container/codec detection | A magic-bytes sniffer | ffprobe `format_name`, `codec_name`, `disposition.attached_pic` | Demuxer-level truth; the custom approach is what the VM exists to avoid |
| Process isolation | Seccomp/namespace code | Firecracker's built-in seccomp + container flags | Maintained by AWS; verified working |
| Exact-size view of a file on a virtio disk | dm-linear, loop devices, a copy of the file | second 512-byte drive + `concat:`/`subfile` in ffprobe | Block devices cannot express a partial sector; a copy of a multi-GB film is not acceptable |
| ext4 image | loop mount in a privileged build | `mkfs.ext4 -d <dir> -O ^has_journal` | Works unprivileged inside `docker build` (verified, 256 MB image) |
| Atomic sidecar writes | custom locking | write temp file then `os.replace` | POSIX-atomic on one filesystem |
| Hand-off copy | `shutil.copy` fallback | `os.link`, fail closed on any `OSError` (D-48) | Copy doubles disk use and breaks the seeding link |
| HTTP client | raw sockets | httpx (already a dependency) | Timeouts, retries, `respx` mocks |
| Per-VM secret | `random` | `secrets.token_hex(8)` | The nonce is a trust boundary against hostile console output |

**Key insight:** every hard part of this phase is already solved by a tool that exists on the box (Firecracker, ffprobe's protocol layer, `mkfs.ext4 -d`, `os.link`); the work is wiring, ordering and failure policy, not new mechanisms.

## Common Pitfalls

### Pitfall 1: The jailer does not fit a hardened container (D-71 as written)
**What goes wrong:** `jailer ... --exec-file firecracker` fails with `Failed to pivot root: Operation not permitted`.
**Why it happens:** the jailer calls `unshare`, `mount`, `pivot_root`, `mknod /dev/kvm`, `chown`, then drops to a uid [CITED: firecracker docs/jailer.md]. Reproduced here: with `--cap-drop ALL --cap-add SYS_ADMIN,MKNOD,CHOWN,SETUID,SETGID,SYS_CHROOT,DAC_OVERRIDE,FOWNER` and Docker's default seccomp profile it fails with the error above [VERIFIED: ran it]; the same command with `--security-opt seccomp=unconfined` boots the VM [VERIFIED]; `apparmor=unconfined` alone changes nothing [VERIFIED]. Separately, the jailer needs the file inside its chroot ("hard links or copy" [CITED: jailer.md]); a hardlink from the read-only quarantine mount into a tmpfs jail fails `Cross-device link` [VERIFIED]. The chroot also bind-mounts itself non-recursively, so pre-mounting the file is not an option (reading of jailer.md, not tested).
**How to avoid:** use Pattern 1 (no jailer). The container already gives a mount namespace, a non-root uid, cgroup limits (`mem_limit`, `pids_limit`, `cpus`), a read-only root, a read-only data mount and no network; Firecracker's seccomp stays on. If the user insists on the jailer: custom seccomp profile allowing the five syscalls, SYS_ADMIN, and a read-write mount of the same filesystem as quarantine for hardlinking, which gives the sandbox container write access to the media tree. That is worse than no jailer.
**Warning signs:** a compose file with `security_opt: seccomp=unconfined` or `cap_add: SYS_ADMIN` on the sandbox service. Add an infra invariant that forbids both.

### Pitfall 2: `/dev/kvm` group and uid
**What goes wrong:** Firecracker exits with a permission error opening `/dev/kvm` as a non-root user.
**Why it happens:** the node is `crw-rw---- root:<gid>`; uid 10001 without that group gets "no-access" [VERIFIED]. Root without capabilities can open it (owner rw) [VERIFIED], but root is the wrong default.
**How to avoid:** non-root user plus `group_add: ["<gid>"]`. The gid is 993 on this host and in Docker Desktop's VM [VERIFIED: `stat` on both], but it is distribution-specific, so write it to `.env` as `KVM_GID` using `stat -c %g /dev/kvm` and have the doctor check that the runner can open the device.
**Warning signs:** runner `/health` reports `kvm: false`.

### Pitfall 3: A bare virtio disk breaks MP4 and AVI probes
See Pattern 2. Without the fix, roughly every MP4 whose `moov` atom is last and whose size is not a multiple of 512 is falsely rejected.

### Pitfall 4: ffprobe option and output traps
- `-nostats` is an ffmpeg option; ffprobe answers "Option not found" and exits 1 [VERIFIED: ran it].
- stdout and stderr share the serial console; do not parse a mixed stream (Pattern 3).
- `-show_entries` should list fields explicitly. A plain `-show_format -show_streams` prints all tags, so a hostile file could produce a huge output; with the field list the output is a few hundred bytes [VERIFIED].
- `devtmpfs` is auto-mounted by the kernel (`CONFIG_DEVTMPFS_MOUNT=y`), so `mount -t devtmpfs` in init prints "Resource busy"; harmless, redirect it.
- ffprobe reports `format.size` as 0 for a bare block device; the backend must use the host `stat` size for the bitrate check.

### Pitfall 5: Full Firecracker guest config build time
**What goes wrong:** `microvm-kernel-ci-x86_64-6.18.config` compiled `drivers/media`, NFS, netfilter and more; after 1287 s (21 min) of compiling on 8 threads it still had not linked, and I stopped it [VERIFIED: build log]. Expect an N100 to be 2-3x slower [ASSUMED].
**How to avoid:** `make tinyconfig` + `scripts/kconfig/merge_config.sh -m` with the committed 38-line fragment (listed in Code Examples). Built in 7m50s on the same machine, 13.6 MB `vmlinux`, boots and probes correctly [VERIFIED]. Docker layer caching makes it a one-time cost. Further trimming (drop `CONFIG_NET`, which pulled in ethtool) is possible but untested.

### Pitfall 6: Hardlink permission model
**What goes wrong:** `ln: Operation not permitted` when the backend links a qBittorrent-owned file.
**Why it happens:** `fs.protected_hardlinks=1` (value read inside a container: 1 [VERIFIED]) forbids linking files you do not own and cannot read+write. Backend today runs as uid 10001 (`useradd --system --uid 10001`, `USER flatflix` [VERIFIED: backend/Dockerfile]) while qBittorrent writes as `PUID` (default 1000).
**Tested matrix on a real bind mount in WSL ext4** [VERIFIED]: one bind, uid 10001 -> EPERM; uid 1000 -> linked; uid 0 without caps -> EPERM; two separate binds, uid 1000 -> `Cross-device link`.
**How to avoid:** `user: "${PUID:-1000}:${PGID:-1000}"` on the backend service and one `DATA_ROOT` bind (D-44). The existing `init-host-dirs.sh` already sets owner `PUID:PGID` and mode 0775 for its folders; extend it for `quarantine/*` and `rejected` (mode 0700). Add a startup self-test in the backend: create a temp file in `quarantine/`, `os.link` it into `media/`, unlink both, log one ERROR and flag the doctor if it fails (covers EXDEV, uid and drvfs at once). On WSL, `DATA_ROOT` must live in the Linux filesystem, not under `/mnt/c` (drvfs hardlink behaviour) [ASSUMED].

### Pitfall 7: The category edit cannot be trusted to leave old torrents alone, and legacy torrents look unverified
**What goes wrong:** after the save paths change, every Phase 1-2 torrent is "finished, category Film, no verified tag", so a naive poller would try to probe files that sit in `/media/...`, or the list would show them as Checking; and `cancel_deletes_files` / Remove could delete real films from media.
**How to avoid:** the candidate rule includes "`save_path` under the quarantine root" (Pattern 6); `deleteFiles` is true only for torrents whose save path is under quarantine (the D-47 amendment must key on the path, not on state, because legacy files in media are the only copy). This replaces the Phase 2 rule that keeps files of any torrent that ever finished (review fixes WR-01..WR-05) for quarantine torrents only; keep that rule for everything else. Note `plain_state(row)` takes only the row today and its tests call it that way; it needs settings (or the quarantine root) passed in.

### Pitfall 8: Name and key collisions in the list API and the smoke script
- `JobState.REJECTED = "rejected"` exists already for "no allowlisted video inside" and `messages.js` maps `rejected` to "This file doesn’t contain a video. Try another result." [VERIFIED: backend/app/download/jobs.py:29, frontend/src/messages.js]. The new probe failure must use a different API value (recommended `check_failed`) with its own message key, or the household reads the wrong text.
- `scripts/smoke.py` asserts the exact item key set `{"id", "name", "type", "state", "progress", "eta_seconds", "action"}` and an enumerated state set that includes `"preparing"`, `"downloading"`, `"stalled"`, `"ready"`, `"problem"`, `"rejected"`... [VERIFIED: scripts/smoke.py:380-387]. Adding `checking`, `check_failed` and a skipped-files count means updating smoke, `listing.py`, `_job_item()` (same keys on every row) and their tests together.
- D-76 vs D-64: `scripts/smoke.py all` downloads a Blender open movie as type `film` [VERIFIED: smoke.py:472-480]; the film minimum is 40 min, and those films run roughly 10-15 min [ASSUMED from training knowledge], so the smoke download would be rejected. Smoke must run with a lowered `MIN_FILM_DURATION_MINUTES` (document it, or have `smoke.py` print a clear instruction), not silently pass.

### Pitfall 9: Limits of the plausibility rules (set expectations, do not over-test)
- A **grossly** truncated MKV keeps its declared duration (60 s) while its size shrinks, so the bitrate band catches it (200 KB / 60 s = 26 kbps < 100 kbps) [VERIFIED]. A file cut at 50 % still looks plausible. Completeness of real downloads is guaranteed by BitTorrent piece hashing, not by this check.
- A 4K remux above 100 Mbps would be rejected by the default band (D-65); env-configurable.
- The 60 s test fixtures fail D-64 (40 min) by design: the opt-in suite must lower the minimums through settings or generate a long enough low-bitrate fixture.
- `.mkv` that is really WebM passes (`matroska,webm` is one demuxer name).

### Pitfall 10: Cancel racing the verifier
Cancel during Checking deletes the torrent with files (D-53). If the verifier is mid-probe, the later link or move hits `FileNotFoundError`: treat that as "aborted", not "rejected". Share one per-hash lock between `pipeline.cancel()` and the verifier and check a cancel flag right before the hand-off (Pattern 5).

### Pitfall 11: Pinning the ffmpeg apk by exact revision rots
Alpine's mirror directory for v3.24 community lists only the current revision of each package (`ffmpeg-8.1.2-r0.apk` plus the separate `ffmpeg6`/`ffmpeg7` packages) [VERIFIED: directory listing this session]; when Alpine ships `8.1.2-r1` an exact pin stops building, which would break INFRA-05 ("fresh Ubuntu machine from the repo"). Recommended: pin the Alpine image tag and apk signature verification, install `ffmpeg` unpinned by default, expose `ARG FFMPEG_APK_VERSION=` for an exact pin, write the resulting version to the image (`/etc/fx-versions`) and report it from `GET /health` and in the audit line. Needs user confirmation (A3).

### Pitfall 12: Non-standard host kernels
Firecracker validates host kernels 5.10, 6.1 and 6.18 only [CITED: kernel-policy.md]. The WSL2 host here runs 5.15.167.4 and works [VERIFIED]. Ubuntu Server's stock kernel is not on the list; expect it to work but record the actual `uname -r` in the setup notes [ASSUMED].

### Judge skeleton (backend, pure)
```python
# backend/app/quarantine/rules.py  -- values below are the D-64..D-67 defaults
FAMILY = {".mkv": "matroska", ".mp4": "mov", ".m4v": "mov", ".avi": "avi"}  # D-66; token inside format_name

def judge(ext: str, facts: dict, size_bytes: int, *, min_minutes: float, min_bps: int, max_bps: int):
    names = set(str(facts.get("format", {}).get("format_name") or "").split(","))
    if FAMILY.get(ext) not in names:
        return Fail("container_mismatch")
    videos = [s for s in facts.get("streams", [])
              if s.get("codec_type") == "video"
              and s.get("codec_name") not in (None, "", "unknown", "none")
              and not (s.get("disposition") or {}).get("attached_pic")]
    if not videos:
        return Fail("no_video_stream")
    try:
        duration = float(facts["format"]["duration"])
    except (KeyError, TypeError, ValueError):
        return Fail("no_duration")
    if not duration > 0 or duration < min_minutes * 60:
        return Fail("duration")
    bps = size_bytes * 8 / duration
    return Pass() if min_bps <= bps <= max_bps else Fail("bitrate")
```
(`Pass`/`Fail` are the planner's types; use the host `stat` size, never ffprobe's.)

### Runner HTTP contract (recommended, stable)
```
POST /probe   {"path": "Film/Some.Movie/movie.mkv"}      # relative to the quarantine root only
200 {"status": "ok" | "probe_failed" | "timeout",
     "ffprobe_exit": 0, "size_bytes": 1669418, "vm_ms": 520,
     "format": {"format_name": "...", "duration": "60.023152", "nb_streams": 2},
     "streams": [{"index": 0, "codec_type": "video", "codec_name": "h264", "attached_pic": false, "width": 320, "height": 240}],
     "stderr": "<=1 KiB printable"}
400 invalid_path (absolute, "..", NUL, backslash, symlink anywhere, outside root)   404 not_found   409 not_regular_file
503 {"error": "runner_unavailable", "why": "kvm" | "artifacts" | "boot"}           # host fault, never a rejection
GET /health   200 {"ok": true, "kvm": true, "firecracker": "1.17.0", "kernel": "6.18.58", "ffmpeg": "8.1.2-r0"}
POST /selftest  boots a VM on a tiny clip baked into the image; used by the doctor
```
Path handling in the runner: reject early on the string, then `os.path.realpath` and require it to equal the lexical join (no symlink hops) and `is_relative_to(root)`; `os.lstat` must say regular file; require size >= 1 MiB (smaller cannot be a film and a zero-size drive is refused by Firecracker [ASSUMED]).

### Audit lines (extend `backend/app/audit.py`, same `key=value` + `_text()` escaping)
`event=quarantine.rejected name=<_text> file=<_text> reason=<token> format=<token> codec=<token> duration=<token> size=<int> ffmpeg=<token>`; also `quarantine.passed`, `quarantine.runner_unavailable why=<token>`, `quarantine.link_failed errno=<token>`, `quarantine.purged count=<int>`. ## Open Questions

1. **Jailer (D-71) vs hardened container**
   - What we know: the jailer needs SYS_ADMIN and `seccomp=unconfined` in Docker and cannot receive the film from a read-only mount without a copy; direct Firecracker in a cap-less container works and is fast.
   - What's unclear: whether the user values the jailer's chroot enough to accept a weaker container.
   - Recommendation: amend D-71 to "hardened container is the jail"; enforce with infra invariants (no `privileged`, no `cap_add`, no `seccomp=unconfined`, `read_only`, `cap_drop: [ALL]`, quarantine mount `read_only`, internal network).

2. **Legacy Phase 1-2 torrents after the path change**
   - What we know: they keep their old paths, lose auto-TMM on the category edit, and report `missingFiles` when `/media` disappears from the container.
   - What's unclear: whether to add an optional compat mount or just document removing them in the WebUI without deleting files.
   - Recommendation: document the removal; no compat mount (D-49: no migration code). They leave the downloads list after 7 days anyway.

3. **Name collision at hand-off** (two torrents containing `Movie.mkv`): recommended unique suffix; Phase 4 renames. Confirm or choose "fail closed and alert".

4. **A runner that stays down for hours**: D-58 keeps every row in Checking. Should the list switch to a `problem`-style state after N hours so the household is not left waiting silently? Recommended: yes at 6 h, audit line either way.

5. **Where the opt-in suite reaches the runner**: the runner is on an internal network with no published port. Recommended: extend `docker-compose.admin.yml` to publish `127.0.0.1:8090` for the sandbox (mirrors the qBittorrent admin override and `QBIT_TEST_URL`), allow it in the infra invariants, tests write fixtures under `DATA_ROOT/quarantine/.fx-test/`.

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Malicious media exploits an ffprobe/demuxer bug | Elevation of Privilege | runs in a Firecracker microVM with no NIC, read-only drives, 256 MiB, 60 s, destroyed after; `-format_whitelist`, `-protocol_whitelist file,concat,subfile` limit the parsing surface further |
| VM escape toward the host | Elevation of Privilege | Firecracker seccomp (default on), non-root uid, cap_drop ALL, no-new-privileges, read-only rootfs, quarantine ro, no network, pids/mem limits; jailer intentionally not used (A1) |
| Hostile console output forges a "pass" | Spoofing | per-VM random nonce on the kernel command line; only nonce-framed lines parsed; ffprobe output restricted with `-show_entries`; judge works on typed facts |
| Path traversal / symlink in the probe request | Tampering | relative path only, realpath equals lexical join, lstat regular file, containment check, `O_NOFOLLOW`-style checks in backend link code |
| TOCTOU between probe and hand-off | Tampering | compare inode/size/mtime before linking; files are torrent payload only qBittorrent touches |
| Output flood from a crafted file | Denial of Service | field-restricted ffprobe output, stdout read cap, wall-clock kill, `pids_limit`, guest `timeout -s KILL 40` |
| Fail-open when the sandbox is down | Elevation / Tampering | D-58: stay in Checking, never link without a pass; judge returns pass only on `status == "ok"` |
| Filename injection into logs | Repudiation | audit helpers `_text()` (JSON-escaped, 200 chars) for every file and torrent name |
| Rejected file reaches Jellyfin | Information Disclosure / Tampering | `rejected/` outside `media`; Jellyfin (Phase 4) mounts only `media` read-only |
| Container escape through `/dev/kvm` misuse | Elevation of Privilege | only `/dev/kvm` device node added; infra invariant: `devices == ["/dev/kvm:/dev/kvm"]`, no `privileged`, no `cap_add`, no `seccomp=unconfined` |
