# Phase 02.1 — UI Design Contract (delta)

> Visual and interaction contract for the new Downloads-row states this phase adds: Checking, "didn't pass the safety check", and Ready with a note. Generated by gsd-ui-researcher, verified by gsd-ui-checker. English only (UI, copy, docs).

This phase is backend and infra. Its only household-facing surface is the Downloads list in the existing Preact + Vite portal. **Everything in `02-UI-SPEC.md` still applies unchanged** (design system, spacing, typography, color, tab bar, polling, outage, cancel and remove interaction, motion, CSP rule). This file lists only what is new or changed. Where a section below says "no change", the Phase 02 contract is the source of truth.

Sources: CONTEXT.md D-53, D-56, D-61, D-62, D-77, D-78 (locked); RESEARCH.md Pattern 6, Pitfall 8, A10 (API names); existing `frontend/src/DownloadRow.jsx`, `messages.js`, `styles.css`, `backend/app/download/listing.py` (read 2026-10-23). No question was put to the user: CONTEXT and the Phase 02 contract answered every item; the remaining choices are listed under "Defaults chosen" in the orchestrator return.

## States and Row Content

### API contract the frontend relies on

Names follow RESEARCH.md Pattern 6 and Pitfall 8 (A10). The backend decides states and actions; the frontend only maps a code to words.

| Field | Change |
|-------|--------|
| `state` | Two new values: `checking` and `check_failed`. **Do not reuse `rejected`**: that value already means "no video inside" and has its own text (Pitfall 8) |
| `skipped` | New integer on every row (same keys on every row, as `smoke.py` asserts). Number of **video** files in this torrent that failed the check; `0` when none. Subtitle failures are never counted or shown to the household. The planner may pick another key name but must change `listing.py`, `_job_item()`, `smoke.py` (key set and state set) and the frontend tests together |
| `action` | `checking` rows carry **`cancel`** (D-53). Today `cancel_deletes_files()` returns false for any finished torrent, so a Checking row would otherwise get `remove`; the quarantine rule must make it `cancel` for a torrent whose save path is under quarantine and which has no verified tag. `check_failed` rows carry `null`. `ready` rows carry `remove` |
| ordering | `checking` rows count as active (listed with preparing, downloading and stalled rows, newest first); `check_failed` rows sort with the other failed rows |
| windows | `ready` rows (with or without a note) stay 7 days from the moment they became Ready (D-28 amended in CONTEXT discretion); `check_failed` rows stay 24 h (D-56) |

### Download row: state table (additions to the Phase 02 table)

```
li.download
  div.download-name          {name}                       unchanged
  div.download-main
    span.badge               Movie | TV Series            unchanged; kept for check_failed rows (type comes from the stored category)
    span.download-state      [spinner] Checking…          16px / 600, tone per table above
  p.download-hint.muted      Making sure the file is safe to watch. It can take a few minutes.     checking only
  p.download-note            1 file didn’t pass the safety check.                                  ready with skipped > 0 only
  div.download-action        Cancel download | Remove from list | nothing
```

| `state` | State text | Bar | ETA | Hint / note | Action |
|---------|-----------|-----|-----|-------------|--------|
| `checking` | `MSG.stateChecking` with the existing `.spinner` (`aria-hidden`) | none | none | muted hint `MSG.checkingHint` | Cancel download (one in-row confirm, as D-32) |
| `check_failed` | `MSG.checkFailed` (warn), shown as the state text | none | none | none | none (no dismiss; leaves the list after 24 h) |
| `ready`, `skipped` = 0 | Ready | 100, green | none | none | Remove from list |
| `ready`, `skipped` >= 1 | Ready | 100, green | none | `.download-note` with `MSG.skippedOne` or `MSG.skippedMany` | Remove from list |

Implementation shape (mirrors the existing `STATES` map in `DownloadRow.jsx`):
- `checking: { text: MSG.stateChecking, tone: 'normal', bar: null, spinner: true, hint: MSG.checkingHint }`
- `check_failed: { text: MSG.checkFailed, tone: 'warn', bar: null }`
- the note renders only when `item.state === 'ready' && item.skipped > 0`, as a Preact text child (never `dangerouslySetInnerHTML`); count 1 uses `skippedOne`, any larger count uses `skippedMany` with `{n}` replaced by the number (same substitution style as `etaMinutes`).

Unchanged rows: `preparing`, `downloading`, `stalled`, `problem`, `rejected`, `unsupported`, `unavailable`, `failed`. A `ready` legacy row (Phase 1-2 torrent saved straight into media, D-49) renders as before with `skipped` 0.

### Lifecycle the household sees

Preparing → Downloading → **Checking…** → Ready (7 days, then it leaves the list), or → "This file didn’t pass the safety check. Try another result." (24 h, then it leaves). A mixed pack ends as Ready plus the note. "Ready" never appears before the files are in the media folder (D-53).

### Checking for a long time (D-58, D-78)

While the checker is unavailable the row simply stays in Checking with no extra message (the household cannot fix it and the admin has the doctor and audit lines). After about 6 hours the backend switches the row to the existing `problem` state (text "Problem" plus `MSG.problemBody`, action Cancel download). No new copy and no new state code.

### Outage and stale list (D-36)

No change: the new states are greyed with the rest of the list (`.is-stale`, opacity 0.6), Cancel and Remove are disabled and any open confirm panel closes.

### Admin-visible surface

None in the portal (D-60, D-59): the admin learns of rejections from the `quarantine.rejected` audit line and the doctor, both outside the browser. No admin page, no admin-only control, no admin-only copy in `messages.js`, and no new portal route is part of this contract. A false rejection is released by a documented manual host step, not by UI.

### Search tab

No change. A torrent removed after a failed check is not a Search-row state: the Search job already ended at "Started ✓".

### Focal point

Unchanged: the first row's name and its progress bar or state. For a Checking row the focal point inside the row is the state text with its spinner (the only moving element in that row); for a `check_failed` row it is the warn-tone message. Nothing in the new states uses the accent.

## Interaction Contract

Everything in Phase 02 stands (5 s polling that pauses when the page is hidden, rows replaced in place keyed by `id`, no gestures, no hover-only affordances, motion limited to the `.spinner` and native progress, `prefers-reduced-motion` slows the spinner to 3 s). Additions:

### Cancel during Checking (D-53)

Same single in-row confirm as D-32 (outlined "Cancel download", then "Cancel this download?" with "Yes, cancel" / "No, keep it", focus on "No, keep it", Escape closes, one panel open at a time, "Cancelling…" in flight, 204 or 404 removes the row, failure shows `MSG.actionFailed`). Only the body line changes with the row's state, chosen at render time:

| Row `state` | Confirm body |
|-------------|--------------|
| `preparing`, `downloading`, `stalled` | `MSG.cancelConfirmBody` "The partly downloaded files will be deleted." (unchanged) |
| `checking`, `problem` | `MSG.cancelConfirmBodyDone` "The downloaded files will be deleted." (the download is finished, or its state is unknown, so "partly" would be wrong) |

If a row moves from Downloading to Checking while its confirm panel is open, the panel stays open (action is still `cancel`) and the body line switches to the new text on the next render. If a Checking row becomes Ready or `check_failed` while the panel is open, the action stops being `cancel` and the panel closes automatically (existing rule 6), so the user is never asked to cancel a finished or rejected download.

### Remove from list (Ready rows)

No visible change: one tap, no confirm, "Removing…" in flight. Under D-47 the backend now deletes the quarantine link with the torrent; the film stays in the media folder, so the household still loses nothing and the label and the absence of a confirm remain correct. Do not add a confirm or change the label.

### Rejected rows

No action, no dismiss control, no retry button (the user goes back to Search and picks another result, which the message says). Not focusable beyond the page's normal flow.

### Screen readers

State changes are not announced (the list is not a live region, same as Phase 02). The Checking spinner is `aria-hidden`; the state text "Checking…" is real text, so each row reads correctly on a manual pass.

## Copywriting Contract

All strings live in `frontend/src/messages.js` as `MSG` keys (components never inline strings). Use the typographic apostrophe `’`. Rules from Phase 02 hold: plain words, sentence case, no exclamation marks, no status codes, no qBittorrent terms. **Also never in household copy: quarantine, sandbox, probe, ffprobe, scan, virus, malware, reject.** "Safety check" is the only name for this step.

| Element | Key | Copy |
|---------|-----|------|
| Primary CTA (this phase) | none new | The only controls on these states are the existing "Cancel download" (`cancelDownload`) and "Remove from list" (`removeFromList`); no new button exists in this phase |
| State: checking | `stateChecking` | Checking… |
| Checking hint | `checkingHint` | Making sure the file is safe to watch. It can take a few minutes. |
| Error state: file failed the check (state text on the row) | `checkFailed` | This file didn’t pass the safety check. Try another result. |
| Ready-row note, one file | `skippedOne` | 1 file didn’t pass the safety check. |
| Ready-row note, several files | `skippedMany` | {n} files didn’t pass the safety check. |
| Empty state heading | `downloadsEmptyTitle` (existing) | No downloads yet |
| Empty state body | `downloadsEmptyBody` (existing) | Search for a movie or series and tap Download. It will show up here. |
| Error state: long-stuck check | `stateProblem` / `problemBody` (existing) | Problem / Something is wrong with this download. Ask the admin to take a look. |
| Error state: action failed (existing) | `actionFailed` | That didn’t work. Try again. |
| Destructive confirmation | `cancelConfirmTitle` + `cancelConfirmBodyDone` (new body) | Cancel download: "Cancel this download?" / "The downloaded files will be deleted." (shown for `checking` and `problem` rows; other rows keep "The partly downloaded files will be deleted.") |
| Confirm buttons, in-flight labels | existing | Yes, cancel / No, keep it / Cancelling… / Removing… |

New `messages.js` keys: `stateChecking`, `checkingHint`, `checkFailed`, `skippedOne`, `skippedMany`, `cancelConfirmBodyDone`. Existing `rejected` (no video inside) keeps its text, "This file doesn’t contain a video. Try another result.", and is not touched.

Destructive actions in this phase:

| Action | Confirmation approach |
|--------|----------------------|
| Cancel download while Checking (deletes the quarantined files and the torrent) | One in-row confirm tap, as D-32, with the `checking` body above |
| Remove from list (Ready row; deletes only the quarantine link, the film stays in media) | None; unchanged |
| Auto-purge of rejected files after 7 days | Not a user action; no UI |

No new error banner, no toast and no modal is introduced.
