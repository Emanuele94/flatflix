# Phase 02 — UI Design Contract

> Visual and interaction contract for the Downloads tab, the tab bar, and the throttle / cancel messages. Generated by gsd-ui-researcher, verified by gsd-ui-checker. English only (UI, copy, docs).

Everything here extends the Phase 1 portal (`frontend/src/`). Values marked "existing" were read from `frontend/src/styles.css`, `messages.js`, `App.jsx`, `ResultRow.jsx` and must not change. New CSS is appended to `styles.css`; there are no design tokens in the repo today (colors and sizes are literals), so this contract names the existing literals instead of inventing a token system.

Sources: CONTEXT.md D-25..D-39 (locked), RESEARCH.md Patterns 1, 2, 6, 7, 8 and Pitfalls 5, 6, 11, 13, 15 (locked), existing frontend (locked). Anything not covered by those is listed under "Defaults chosen" in the orchestrator return.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-written CSS in `frontend/src/styles.css`; Preact 11 + Vite 8) |
| Preset | not applicable |
| Component library | none (own components: `Search`, `ResultRow`, `Login`, new `Downloads`, `DownloadRow`) |
| Icon library | none. Text glyphs only (existing `✓` in "Started ✓"). No icon font, no SVG sprite, no third-party URL (the `no-third-party` test and CSP `default-src 'self'` forbid it). |
| Font | System stack, existing: `system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`. Nothing is loaded from outside the origin. |

Detection evidence (run 2026-10-22 in `frontend/`): no `components.json`, no `tailwind.config.*`, no `postcss.config.*`; `package.json` runtime dependency is `preact` only. shadcn is a React/Radix kit, the project forbids third-party UI code (RESEARCH "Don't Hand-Roll": no UI kit), so the shadcn gate resolves to `Tool: none`. Registry safety gate: not applicable.

CSP rule (01-04): no inline `style=""` attributes anywhere. Every visual state is a class name or an attribute (`hidden`, `value`, `max`, `disabled`, `aria-*`).

## Spacing Scale

Existing app mixes `rem` and `px`; new work uses these px values only (root font-size is 16px, so 1rem = 16px).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between state label and ETA text; tab underline offset |
| sm | 8px | Gap between badge / state / ETA chips; gap between the two confirm buttons; gap between progress bar and % text; space above a row action |
| md | 16px | Page padding (existing `main.app` padding 1rem); banner padding; space between tab bar and panel |
| lg | 24px | Space above the empty-state block; space between a row's last line and the next row's divider group when the confirm panel is open |
| xl | 32px | Not used in this phase |
| 2xl | 48px | Minimum touch target height (buttons, tabs) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Row vertical padding is **12px** (existing `.result { padding: 12px 0 }`). Downloads rows reuse the same value so Search and Downloads lists look like one family. 12px is a multiple of 4.
- Touch targets are exactly 48px minimum height (existing global rule `button, input, select { min-height: 48px }`); the 48px is a size floor, not a spacing step.
- Progress bar height: 12px (a size, not spacing).

Layout: single column, `max-width: 40rem` centered (existing `main.app`). Verified width range: 320px to 640px phones. No horizontal scrolling at 320px; every text container wraps (`overflow-wrap: anywhere`, existing on `.result` and `.result-name`).

## Typography

New components use exactly these four sizes and two weights. They are all values the app already uses.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / row name | 18px (body, existing); name is the same size at weight 600 | 400 body, 600 name | 1.4 (existing body line-height; 1.5 is not used so the Phase 1 screens stay identical) |
| Label / state text / buttons / tab labels | 16px (`1rem`, existing on controls) | 600 | 1.4 |
| Meta (ETA, %, hints, `.muted`) | 13.6px (`0.85rem`, existing `.muted`) | 400 | 1.4 |
| Heading | 28px (`1.75rem`, existing `h1`) for the app title only. The empty-state title uses 18px / 600 and is an `h2`. | 600 | 1.2 (existing h1 is unset; set `line-height: 1.2` on `h1` only if touched, otherwise leave) |

Weights declared for new work: **400 and 600 only.**

Inherited exceptions (existing classes reused untouched, not re-declared): `.badge` is 12.8px / 700 and `.result-main` is 18.4px / 700. The Downloads row reuses `.badge` as is. New rules must not introduce a third weight or a fifth size.

Numbers use `font-variant-numeric: tabular-nums` on the % text so the value does not jitter on each 5 s refresh.

## Screen Structure

### App shell (edit `App.jsx`)

```
header.app-header        flatflix                    [Log out]            (existing)
main.app
  div[role=tablist]      [ Search ]  [ Downloads ]                         (new, directly under header)
  section#panel-search   role=tabpanel, aria-labelledby=tab-search, hidden when Downloads active
    <Search/>            ALWAYS MOUNTED (RESEARCH Pitfall 5, D-26)
  section#panel-downloads role=tabpanel, aria-labelledby=tab-downloads
    <Downloads/>         mounted only while its tab is active (stops polling on unmount, D-31)
```

- Default tab after login or reload: **Search**. Active tab is in-memory only (not persisted).
- `styles.css` must add `[hidden] { display: none !important; }` (author CSS would otherwise override the attribute).
- Tabs are `<button type="button" role="tab" aria-selected="true|false" aria-controls=... id=...>` inside `role="tablist"`. The explicit `role="tab"` keeps them out of the `button` role query, so existing `getByRole('button', { name: 'Search' })` tests stay unambiguous (RESEARCH Pitfall 6).
- Keyboard: Left/Right arrow moves selection between the two tabs; Home/End select first/last; roving `tabindex` (active tab 0, other -1).
- Tab bar look: two equal-width tabs filling the row (`flex: 1`), 48px high, label 16px / 600, no background, bottom border 1px `#ddd` on the bar and 3px `#b3141f` under the active tab (inactive tab: 3px transparent so nothing shifts). Active label `#1b1b1f`, inactive `#666`. This is deliberately a different shape from the Movie / TV Series segmented toggle in the Search form, so the two controls are not confused.
- No count badge on the Downloads tab (counting needs polling while the tab is hidden, which D-31 forbids).

### Downloads panel (`Downloads.jsx`, view only plus polling hook)

Top to bottom:
1. **Service banner** (only when needed), `<p class="banner" role="status">` (existing yellow banner style, `#fff3cd` / `#5c4400`, centered, 16px padding). Sits inside the panel above the list.
2. **List** `<ul class="downloads">` (no bullets, no margin, same as `.results`), wrapped so `.is-stale` can grey it.
3. **Empty state** or **loading** instead of the list when applicable.

### Download row (`DownloadRow.jsx`, pure view)

```
li.download
  div.download-name          {name}                                   18px / 600, wraps, no truncation
  div.download-main
    span.badge               Movie | TV Series                         existing .badge; omitted when type is null
    span.download-state      Downloading                               16px / 600, tone per state table
    span.download-eta.muted  about 20 min left                         only when eta_seconds is not null
  div.download-progress      (hidden for problem and failed-job rows)
    progress                 max=100 value={n}                         12px high, full width, native element
    span.muted               42%                                       tabular-nums; omitted when preparing
  div.download-action
    button                   Cancel download | Remove from list        see Interaction Contract
    (or confirm panel)
```

- Row container: `padding: 12px 0; border-bottom: 1px solid #ddd; overflow-wrap: anywhere` (reuse the `.result` rule or add `.download` with identical values).
- Spacing inside the row: name to main line 4px; main line to progress 8px; progress to action 8px. Chip gap 8px horizontal, wraps onto a second line on narrow phones (`flex-wrap: wrap; gap: 4px 8px`).
- Name is rendered as a Preact text child only (never `dangerouslySetInnerHTML`; names are attacker-controlled).
- `<progress>` styling without inline styles: `appearance: none; width: 100%; height: 12px; border: 0; border-radius: 6px; background: #ddd;` plus `::-webkit-progress-bar` (`#ddd`, radius 6px), `::-webkit-progress-value` and `::-moz-progress-bar` (state color via modifier classes `.is-downloading`, `.is-stalled`, `.is-ready`). Preparing rows use `<progress max="100">` with **no `value` attribute** (indeterminate), which the browser animates natively.
- Accessibility: `<progress aria-label="Progress">`; the % text next to it is `aria-hidden="true"` (the native value is already announced).
- Non-text contrast: every fill color above is at least 3:1 against `#ddd`.

Row content by item `state` (state codes come from the backend; the frontend maps code -> text only, RESEARCH "Anti-Patterns"):

| `state` | State text | Bar | ETA | Action |
|---------|-----------|-----|-----|--------|
| `preparing` | Preparing (with the existing `.spinner`, `aria-hidden`) | indeterminate | none | Cancel download |
| `downloading` | Downloading | value = progress, blue | `formatEta(eta_seconds)` if not null | Cancel download |
| `stalled` | Stalled, plus muted hint "Not moving right now. It may start again by itself." | value = progress, amber | none | Cancel download |
| `ready` | Ready | 100, green | none | Remove from list |
| `problem` | Problem, plus message "Something is wrong with this download. Ask the admin to take a look." (error tone) | none | none | Cancel download |
| `rejected` | `MSG.rejected` (warn tone), shown as the state text | none | none | none |
| `unsupported` | `MSG.unsupportedFormat` (warn) | none | none | none |
| `unavailable` | `MSG.unavailable` (warn) | none | none | none |
| `failed` | `MSG.downloadFailed` (error) | none | none | none (the user retries from Search) |

Failed-job rows have no action and no dismiss control; they leave the list after 24 h (D-29). Their `name` can be null, and their `type` can be null: omit the badge when null.

Name fallback when `name` is null: "Unnamed download" (`MSG.unnamedDownload`). A raw info-hash is never displayed (RESEARCH Pitfall 11).

### Empty and loading (inside the Downloads panel)

- **First load in flight** (no response yet, nothing cached): `<p class="searching" role="status"><span class="spinner" aria-hidden="true"/> Loading your downloads…</p>` (existing `.searching` pattern).
- **Loaded, zero items** (successful response): `h2` "No downloads yet", muted body "Search for a movie or series and tap Download. It will show up here.", then a `.btn.btn-primary` "Go to Search" that switches to the Search tab. Block is left-aligned, 24px above.
- **First load failed** (no list ever loaded): show only the banner. Do **not** show the empty state (it would claim there are no downloads when the truth is unknown). Polling continues; the empty state or list replaces the banner when a response arrives.

### Outage (D-36)

When a poll fails (status 0 or 502 `qbit_unreachable`) and a last-known list exists:
- Banner: "Can’t reach the download service. Retrying…"
- List stays, `.is-stale` (opacity 0.6), every Cancel / Remove / confirm button `disabled`; an open confirm panel closes.
- Polling continues every 5 s. On the first success: banner removed, `.is-stale` removed, buttons re-enabled, no flash or extra message.

When a poll answers 502 `qbit_refused` (wrong qBittorrent credentials, never shown as 401): same stale behavior, banner text "The download service has a problem. Ask the admin." (no retry wording, because retrying will not fix it, but polling still continues quietly).

When the whole portal is unreachable (status 0), the existing top-of-page behavior is unchanged; the in-panel banner says "Can’t reach the download service. Retrying…" (the 5 s poll cannot tell the two apart and does not need to).

A 401 from the session expiring is handled globally by `api()`: login screen, nothing special in this panel.

## Interaction Contract

### Polling (D-31)
- Fetch `GET /api/downloads` on mount, then 5000 ms after each response settles (`setTimeout` chain, not `setInterval`).
- Page hidden (`document.visibilityState === 'hidden'`): no timer. On `visibilitychange` to not hidden: fetch immediately, then resume the chain.
- Switching to Search unmounts `Downloads` (polling stops). Switching back fetches immediately and shows the loading line only if no list is cached in memory for this session; otherwise show the cached list, un-greyed, and refresh in place without a spinner.
- No pull-to-refresh, no refresh button (the list refreshes itself).
- List updates replace rows in place, keyed by `id`, so scroll position and an open confirm panel survive a refresh. Ordering comes from the backend (D-30); the frontend does not re-sort.

### Cancel (in-progress rows: preparing, downloading, stalled, problem) — D-32
1. Row shows an outlined `.btn` "Cancel download" (white, `#888` border, existing `.btn`), full row width, 48px. It is not red and not accent (a calm, non-primary look; the destructive color appears only on the confirm).
2. Tap: the button is replaced in place by the confirm panel (same row, no modal, no layout jump above it):
   - Text, 16px / 600: "Cancel this download?"
   - Muted line, 13.6px: "The partly downloaded files will be deleted."
   - Two buttons side by side, 8px gap, each `flex: 1`, 48px: **"Yes, cancel"** (destructive outline: `#7a0e16` text, `#b3141f` border, `#fdecee` fill) and **"No, keep it"** (neutral `.btn`).
   - Focus moves to "No, keep it" (the safe choice) when the panel opens. Pressing Escape or tapping "No, keep it" closes the panel and returns focus to "Cancel download".
3. "Yes, cancel": both buttons disabled, "Yes, cancel" shows the existing `.spinner` (destructive tone) and the text "Cancelling…". One `DELETE /api/downloads/{id}` is sent (no body, no path or category from the browser, D-35).
4. Success (204) or 404 (already gone): the row is removed immediately from local state, then the next poll confirms. No toast.
5. Failure: the confirm panel closes, the row returns to its normal state and shows `MSG.actionFailed` ("That didn’t work. Try again.", `role="status"`, warn tone) under the button. 502 follows the outage rule instead (banner + greyed list).
6. A confirm panel left open is closed automatically if the row's `action` stops being `cancel` after a refresh (for example the download just finished and became `ready`), so the user is never asked to cancel a finished film.
7. Only one confirm panel is open at a time; opening another closes the first.

### Remove from list (completed rows) — D-33
- Single tap, **no confirm** (reversible: files stay on disk; the film is never deleted from the phone). Label "Remove from list", outlined `.btn`, full row width, 48px.
- While the request is in flight: disabled, `.spinner`, text "Removing…". Success/404: row disappears. Failure: `MSG.actionFailed` under the button.

### Throttling (D-39) — shown in Search, not in Downloads
- A `429 too_many_requests` on `POST /api/search` shows `MSG.throttled` in the existing `.form-error` block under the form (`role="alert"`), same place as other search errors.
- A `429` on `POST /api/download` puts that result row in a new state `throttled`: Download button stays enabled (retry allowed), message under it in warn tone (`row-state row-state-warn`, `role="status"`). No countdown, no `Retry-After` shown.
- No status code or backend text ever reaches the DOM (D-37).

### Search row state added by cancel
- A job that returns `cancelled` (the user cancelled it from Downloads while Search still showed "Preparing") puts the row back to a retryable state with `MSG.downloadCancelled` ("This download was cancelled. Tap Download to start it again.", warn tone), Download button enabled.

### Touch and gestures
- All tap targets >= 48px high; row actions are full row width so a thumb cannot miss them; Cancel and Remove are separated from the row above by at least 8px and from the next row by the 12px padding plus divider.
- No swipe gestures, no long-press menus, no hover-only affordances (phones).

### Motion
- Only the existing `.spinner` rotation and the native indeterminate `<progress>`. Add `@media (prefers-reduced-motion: reduce)` that sets `.spinner { animation-duration: 3s }` (slower, still visible). No transitions on rows, no fade-outs on removal.

Destructive actions in this phase (each listed):
| Action | Confirmation approach |
|--------|----------------------|
| Cancel download (deletes torrent and partial files) | One in-row confirm tap: "Cancel this download?" with "Yes, cancel" / "No, keep it" |
| Remove from list (keeps files) | None; reversible, not destructive to the film |

ETA text (`frontend/src/eta.js`, `formatEta(seconds) -> string | null`), RESEARCH Pitfall 13, rounded coarsely so it does not flicker on each poll:
| Remaining | Output |
|-----------|--------|
| null / not finite / <= 0 | null (nothing shown) |
| < 60 s | less than a minute left |
| 60 s to < 90 min | about N min left; N = ceil(s / 60); once N >= 10 round N to the nearest 5 |
| 90 min to < 24 h | about N h left; N = round(hours), minimum 2 |
| >= 24 h | more than a day left |

Rules for every string: plain words, no status codes, no qBittorrent terms (torrent, seeders, hash, category, path), no "error" wording, no exclamation marks, sentence case. Banners that can clear on their own end with an ellipsis and say "Retrying…"; banners that need a human say "Ask the admin."
