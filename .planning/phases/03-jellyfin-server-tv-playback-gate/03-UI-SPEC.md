# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope statement.** Phase 3 writes **no custom frontend code**. Every screen the household or the admin sees in this phase is **stock Jellyfin web UI** under `/jellyfin` (PC browser and the Hisense VIDAA browser), plus **Markdown docs**. The custom TV app (Home, Library, Detail, Player, `/tv`) is Phase 5 and is not specified here. This contract therefore covers only: (1) Jellyfin settings that change what people see, (2) the Caddy route that decides whether the Jellyfin UI renders, (3) household and admin facing copy in docs, (4) the portal, which gets no visible change. Sections with nothing to specify say "Not applicable — no custom UI in this phase".

Sources: `03-CONTEXT.md` (D-80..D-97), `web/Caddyfile`, `frontend/src/styles.css`, `frontend/src/messages.js`, `docs/setup.md`, `docs/ports-and-media.md`.

**Play-method vocabulary** (the only four values allowed in the Method column; each is derived from Jellyfin's Sessions API `PlayMethod` and `TranscodingInfo`):

| Value in the matrix | Meaning | Jellyfin source | Counts toward "no video transcoding"? |
|---------------------|---------|-----------------|----------------------------------------|
| `Direct play` | File sent as is | `PlayMethod = DirectPlay` | Yes |
| `Remux` | Container changed, streams copied | `PlayMethod = DirectStream`, or `Transcode` with `IsVideoDirect = true` and `IsAudioDirect = true` | Yes |
| `Audio transcode` | Audio re-encoded, video copied | `Transcode` with `IsVideoDirect = true`, `IsAudioDirect = false` | Yes (PLAY-02) |
| `Video transcode` | Video re-encoded | `Transcode` with `IsVideoDirect = false` | **No** |

The helper script (D-88) writes the Method value from those fields and copies Jellyfin's `TranscodeReasons` verbatim into the Reason column. The user adds only the `Picture and sound OK` answer.

**Matrix layout** (one table per group, same columns in every table, one row per clip, rows ordered as listed):

| Column | Content |
|--------|---------|
| ID | Stable short id of the clip, e.g. `A01` (also the clip's file name prefix) |
| Container | `MKV` or `MP4` |
| Video | `H.264`, `HEVC 8-bit`, `HEVC 10-bit` (information group adds `HEVC 10-bit HDR10`) |
| Audio | `AAC`, `AC3`, `EAC3`, `DTS` |
| Subtitles | `none`, `SRT`, `ASS (embedded)`, `PGS (embedded)` |
| Resolution | `1080p` or `2160p` |
| Method | one value from the vocabulary above, or `not tested` |
| Reason | Jellyfin `TranscodeReasons`, or `-` for direct play |
| Picture and sound OK | `yes` / `no` / `not tested` |

Groups, in this order, as H2 headings:

| Heading | Rows | Gates the verdict (D-85, D-86) |
|---------|------|--------------------------------|
| `## 1080p video and audio` | one per codec combination from D-84 (COMPAT-01, COMPAT-02) | **Yes** |
| `## Subtitles` | text subtitles (SRT, ASS) on a 1080p clip (COMPAT-03) | **Yes** |
| `## Image subtitles (PGS) — information only` | PGS clips; add a line "burn-in forced: yes/no" | No |
| `## 4K and HDR10 — information only` | a few 2160p rows | No |
| `## Real-release samples (sanity check)` | public sample files from D-84(b) | No |

**Verdict block** (under `## Verdict`; exactly one of three headline values, then the evidence):

| Headline | When | Required follow-up line |
|----------|------|-------------------------|
| `GO` | Every row in the two gating groups ends in Direct play, Remux or Audio transcode with `Picture and sound OK = yes` | `Phase 5 builds its device profile from the rows marked Direct play or Remux above.` |
| `GO with conditions` | Gating rows pass only for a stated subset (for example no DTS, or MKV only) | One bullet per condition, each tied to a row id, and `Mitigation for the rest: <re-encode / plan B stick / stronger hardware>` |

## Caddy `/jellyfin` Route Contract

This is the one place in the phase where a visual outcome (does the Jellyfin UI render at all) depends on code. Contract for `web/Caddyfile`:

| Rule | Contract |
|------|----------|
| Path match | Both `/jellyfin` and `/jellyfin/*` reach Jellyfin. A bare `/jellyfin` (what a household member types or bookmarks) must end on the Jellyfin web UI, either through Jellyfin's own redirect or a Caddy `redir /jellyfin /jellyfin/ 308`. `handle /jellyfin/*` alone does not match the bare path. |
| Upstream | `reverse_proxy jellyfin:8096`, no path stripping (BaseURL is `/jellyfin`, D-80). WebSocket upgrade works through the default `reverse_proxy` behavior; no extra setting unless the web UI's live status fails. |
| CSP scope | The portal's strict CSP (`default-src 'self'; script-src 'self'; style-src 'self'; ...`) stays **byte for byte** the policy for every route outside `/jellyfin`. Only the `/jellyfin/*` route gets its own policy. The existing `-Server`, `X-Content-Type-Options nosniff`, `Referrer-Policy no-referrer` and `X-Frame-Options DENY` apply to Jellyfin unchanged (Jellyfin needs none of them relaxed; nothing frames it). |
| One policy only | The response from `/jellyfin/*` carries **exactly one** `Content-Security-Policy` header. Two policies are enforced as an intersection, so the strict site-wide one would silently break Jellyfin. Mechanism is the executor's choice (override inside the route and drop any upstream value with `header_down -Content-Security-Policy`, or delete Caddy's and pass Jellyfin's own through), as long as the check below passes. |
| Starting policy for `/jellyfin/*` | Start from Jellyfin's own documented default and loosen only what the pinned version's web client needs, found by opening the browser console on the PC: `default-src 'self'; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self' ws: wss:; font-src 'self' data:; worker-src 'self' blob:; object-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`. No `https:` wildcard and no third-party host (no Cast, no YouTube): the LAN-only, no-egress UI never needs them. Every loosening beyond this line is written next to the Caddyfile route as a one-line comment with the console error that required it. |
| Cache | No `Cache-Control` override on `/jellyfin/*`; Jellyfin sets its own. The portal's `no-cache` and immutable `/assets/*` rules stay on their own routes. |
| Compression | Video and image responses must not be re-compressed; rely on `encode` skipping already-compressed types and confirm a playing stream is not served with `Content-Encoding`. |
| Upstream down | `handle_errors` for `/jellyfin` returns the plain-text line from the Copywriting Contract with the original 502 or 503 status. |

Acceptance checks (re-runnable, belong in the plan's verification):

1. `curl -sI http://127.0.0.1/jellyfin/web/index.html | grep -ci '^content-security-policy'` prints `1`.
2. `curl -sI http://127.0.0.1/ | grep -i '^content-security-policy'` prints the **unchanged** portal policy (`default-src 'self'; script-src 'self'; style-src 'self'; ...`); `infra/tests` gains an assertion that the portal route's policy text is identical to the pre-phase value and contains no `'unsafe-inline'`.
3. On the PC, `/jellyfin` loads the login page with no CSP violation in the browser console, and playback of one clip starts.
4. The same page loads on the TV browser, and playback of one clip starts.
