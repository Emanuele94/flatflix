<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /api/download | Untrusted result_id and type |
| backend -> qBittorrent torrents/add | Backend hands a plugin-provided URL to the engine |
| torrent metadata -> allowlist | Attacker-controlled file names and sizes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-30 | Tampering / Information disclosure | URL sent to qBittorrent (SSRF) | high | mitigate | Browser sends only a result_id; URL comes from the server-side cache filled by search; extra body fields 422 (tested). SSRF is canon and also covered by /gsd-secure-phase |
| T-01-31 | Tampering | multi-line urls field | medium | mitigate | add_torrent raises before any request on CR or LF (tested) |
| T-01-32 | Tampering | file data downloaded before filtering | high | mitigate | stopCondition=MetadataReceived (D-23), priorities 0/1 set and re-read before start, mismatch deletes with files, tag fx-pending + reconcile (A8 residual race accepted: disallowed files are priority 0 before start and the exclusion list is active) |
| T-01-33 | Tampering | category from request (qB auto-creates categories) | high | mitigate | Category only from `qbit_category(settings, type)` with strict Literal type; no set_category method exists; concurrency test |
| T-01-34 | Information disclosure | download responses | high | mitigate | Body is exactly {status, job_id}; hashes, paths, categories never returned (key-set test) |
| T-01-35 | Denial of service | stranded stopped torrents after restart | medium | mitigate | reconcile on startup deletes expired fx-pending torrents and resumes the rest |
| T-01-SC | Tampering | packages | high | mitigate | No new packages; approved lockfiles only |
</threat_model>
